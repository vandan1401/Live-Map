## 3. Pinned constraints

- `plots.status` is a `text` column with a `CHECK` constraint against the four words, not a
  native Postgres `enum` type. D-013's words are explicitly unconfirmed; a `CHECK` is a
  one-line migration to change later, an `ALTER TYPE` is not.
- Legal transitions are enumerated in `docs/decisions/D-013-status-vocabulary.md` only — no
  DB trigger enforces adjacency in M2. Enforcement is `applyPlotTransition()`, M4. M2's
  `CHECK` only restricts to the four valid words, not valid transitions between them.
- `(colony_id, svg_id)` unique constraint lives in the database, not the import script.
- `plot_history` rejects `UPDATE` and `DELETE` via a trigger, not a convention.
- RLS: enabled, permissive (`using (true) with check (true)`) on all three tables, each
  policy carrying a SQL comment citing D-011 and naming M8 as the tightening point.
- The import script writes one `plot_history` row per plot at load time (`changed_by:
  'import'`, `note: 'initial load'`) so a plot never has status without attribution.
- `colonies.id` is the manifest's `colony.id` text value (e.g. `"shree-vatika-2"`), not a
  generated UUID.
- `updated_by` on the initial import is the literal string `'import'` — there's no
  session/auth yet (D-011).

## 6. Failure modes (spec/00-rules.md checklist, applied to this task)

1. **Partial writes** — the import script's plot+history inserts could fail mid-batch.
   Script reports exactly which `svg_id`s succeeded/failed on any error, never a silent
   partial load. The harder version of this rule (concurrent live writes) is M4's.
2. **Idempotency** — a second accidental run of the import script fails loudly on the
   `(colony_id, svg_id)` unique constraint, not a silent duplicate.
3. **Concurrency** — N/A in the D-006 sense; the import is a single-actor batch load
   against a fresh database, not the live multi-user write path.
4. **Orphans** — validated both directions: every manifest plot's `svg_id` must exist as a
   `<path id>` in `colony.svg`, and the reverse. Either mismatch is a hard failure.
5. **Dead computation** — `facing`, `is_corner`, `area_sqft` come only from the manifest;
   nothing in `lib/db`, `lib/colony`, or the import script recomputes them.
