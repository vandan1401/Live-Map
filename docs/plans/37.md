# Plan 37 -- C2/C3: runtime app config (written after the fact, reviewed with plan 36)

Written retroactively: this work was built before plan 36 and the review of 36 correctly
flagged it as unplanned. Tier 2 (`src/lib/*` outside the Tier 1 list; `index.html` and
`public/config.js` change what every PWA load runs).

1. Context: Supabase URL/key were read only from build-time `VITE_*` in
   `src/lib/db/browserClient.ts`. One image must serve the SaaS and every private instance.
2. Task: `src/lib/config/appConfig.ts` (+ test) resolves URL, anon key and
   `deploymentMode` from `window.__APP_CONFIG__` (set by `/config.js`), falling back to
   `VITE_*`; remembers the last runtime config in localStorage for offline PWA launches;
   `browserClient.ts` uses it; `public/config.js` ships empty (`window.__APP_CONFIG__ = {}`);
   `index.html` loads it before the app bundle.
3. Pinned: the SaaS build is unchanged (empty config -> build-time values). `public/sw.js` is
   untouched (it caches only navigations and `/assets/*`, so `/config.js` is always fetched
   fresh; the localStorage copy covers the offline case). Unknown mode strings mean `saas`.
4. Non-goals: hiding features by mode (nothing to hide: no billing/marketing/telemetry),
   bundling Google Fonts (tracked in docs/selfhost/PROGRESS.md), the container entrypoint that
   writes `/config.js` (C5).
5. Acceptance: `src/lib/config/appConfig.test.ts` (5 tests) passes; typecheck and lint clean;
   full suite shows only the 5 baseline failures.
6. Failure modes: no state writes beyond a localStorage convenience copy (wrapped in
   try/catch; the app works without it).
