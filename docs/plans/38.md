## 2. The exact task

Add, under `apps/map/scripts/`:

- `tenant-export.ts` — `pnpm tenant:export --org <uuid> --source-env <file> --out <dir>`
- `tenant-import.ts` — `pnpm tenant:import --in <dir> --target-env <file> [--dry-run]`
- `tenant/` helper modules (each file ≤ 250 lines, invariant 7): connection, column-intersection,
  FK-ordered table list, row streaming, auth rows, storage copy, counts + compare, path guard.
- `package.json`: scripts `tenant:export`, `tenant:import`; devDependencies `pg` + `@types/pg`
  (scripts only; never imported from `src/`). Lockfile updates with it.
- Tests: pure helpers unit-tested (vitest); one live round trip against the local Docker stack.
- `docs/selfhost/` runbook paragraph: how to run it, and how to reach the box's DB (§3).

Behaviour:

1. **Export** (read-only). One `BEGIN ISOLATION LEVEL REPEATABLE READ READ ONLY` transaction for
   every table, so the snapshot is consistent. Order (FK order): `organizations` → `colonies` →
   `plots` → `plot_history` → `auth.users` → `auth.identities`; then Storage objects. Writes to
   `<out>/`: one NDJSON file per table, `storage/<path>` files, and `manifest.json` (org id, export
   time, per-table row counts, per-colony plot and history counts, file sha256s, source column lists).
   Rows are produced in SQL (`row_to_json`/`to_jsonb`) and never parsed into JS numbers/dates.
2. **Import** (target). One transaction. Preflight (all must pass, before any write): target has no
   rows for that `org_id` in any tenant table and no auth user with the org's ids/emails (otherwise
   refuse and print which); column check per table (§3); every `plots.colony_id`, `plot_history.plot_id`
   and `identities.user_id` resolves inside the export; every `plots.svg_id` is present in its
   colony's `svg` (`extractSvgPlotIds`, orphan rule 4); manifest sha256s match the files. Then insert in
   FK order, then upload Storage objects through the target Storage API, then compare counts and
   **roll back the transaction on any mismatch**. `--dry-run` runs everything and ends in ROLLBACK
   (Storage upload is skipped in dry-run; only its object list and sizes are checked).
3. **Counts report**: print per-table counts source vs target (and per colony), never row contents.
   Exit non-zero if any differ.

## 3. Pinned constraints

- **Direct Postgres only** (`pg`), `DATABASE_URL` in the env file. Never printed, never logged, never
  placed on a command line (it holds the DB password).
- **Preserve identity verbatim**: org id, colony ids, plot ids, `svg_id`, `version`, `created_at`,
  `updated_at`, `plot_history.*` including ids and `changed_at`, `colonies.public_token`
  (the old WhatsApp public links keep working), `auth.users.id`, `encrypted_password`.
- **No JS conversion of values.** `*_paise` are `bigint` (invariant 3): they stay JSON strings/ints
  inside SQL-produced JSON and are inserted with `jsonb_populate_recordset(null::<table>, $1)`.
  Timestamps keep microseconds. A test must round-trip a `rate_paise` above 2^53 and a timestamp
  with microseconds.
- **Column compatibility**, per table, by `information_schema` (cloud may lag or lead the box; the
  cloud's migration bookkeeping is not trusted, migrations were hand-applied): exclude generated
  columns (e.g. `auth.identities.email`, `auth.users.confirmed_at`); refuse if the source has a
  non-null value in a column missing on the target; refuse if the target has a NOT NULL column without
  default that the source lacks. Copy only the intersection.
- **Never exported or copied**: `auth.sessions`, `auth.refresh_tokens`, MFA tables, one-time tokens.
  Members log in again (their passwords still work). The org's super-admin is not special: only users
  whose `org_id` matches are moved.
- **Target must be empty for the org** (no merge, no upsert, no `ON CONFLICT`). A second run must
  fail at preflight with a named reason, not append. Never DELETE/UPDATE `plot_history`, never
  disable its triggers.
- **Export contains personal data and password hashes.** `--out` is refused if inside the git work
  tree; files created mode 0600 where the OS allows; the script says to delete the directory after
  cutover. No compression/encryption option in this plan.
- **No new open ports.** Reaching the box's DB is by SSH tunnel to the db container's bridge address
  (`docker inspect` it on the box); do not publish 5432.
- Storage: copy via the Storage API with the service-role key, same object path, no overwrite
  (`upsert: false`); never insert into `storage.objects` directly.
- Quoted numbers: none are tunable. Batch size for streaming is an implementation detail.

## 6. Failure modes (spec/00-rules.md, apps/map — writing state)

1. **Partial writes** — one import transaction; any failure or count mismatch rolls back; Storage
   uploads happen last and a failed upload aborts before COMMIT is issued (commit is the final step).
2. **Idempotency** — preflight refuses a non-empty target for the org; rerun after success or
   failure never appends history. Test 5.
3. **Concurrency** — export uses a single REPEATABLE READ snapshot; writes after the snapshot are
   not in it. Cutover step 1 (freeze edits) is the operator's; the script adds `--verify-source`
   to the export: re-reads source counts and fails if they moved since the manifest.
4. **Orphans** — preflight checks FK closure and `svg_id` ⊆ `colonies.svg` ids before any write.
5. **Dead computation** — `facing`, `is_corner`, `area_sqft`, `version` are copied verbatim; nothing is
   recomputed, no `applyPlotTransition()` call (invariant 4: this is a bulk copy, not a status change;
   `updated_by` and history are preserved exactly, none invented).
