## 1. Context already true

### Measured, this session (2026-08-22) — do not re-derive

The full matrices live in `PROGRESS.md → Deferred`. The load-bearing results:

| Fact | Number |
|---|---|
| Today's Leaflet settle, per discrete zoom step | 198–237 ms |
| Today's zoom, as shipped | 6 fps |
| Today's pan, every configuration tested | 60 fps — **pan was never the problem** |
| Canvas full redraw, whole colony in view, optimised, GPU-flushed | 17.2 ms (≈58 fps) |
| Canvas full redraw, zoomed 4× | 9.9 ms |
| Labels' share of an un-culled canvas frame | 20.6 ms of 37.5 ms — **55%** |
| Culling labels to viewport | −10.1 ms |
| Batching plot fills by status | **0.0 ms — worthless** |
| Batching strokes into one `Path2D` | −1.0 ms |
| Grass pattern over flat fill | +2.3 ms |
| Pick via point-in-polygon | 0.028 ms/click |
| Pick via colour-key buffer | 0.013 ms/click, 2.7 ms to build |
| Two pickers agreed on | 43/43 plot centroids |

Three of these overturn the intuition that produced them and must not be re-litigated:

- **DOM viewport culling made things worse** (260–438 ms/step vs 198–237). The browser
  already clips off-screen content; `display` toggling still forces a style recalc across
  every node. Culling is a win *on canvas* only because we own the draw loop.
- **Batching fills bought nothing.** The cost is pixels rasterised, not draw calls issued.
- **An earlier "3 ms per redraw" figure was wrong** — it timed Canvas2D command queueing,
  not rasterisation. Every number above is `getImageData`-flushed. The real gain is ~12×,
  not 70×.

### Decisions that constrain this

- **D-004 — colony SVGs carry geometry only; one theme, CSS variables, every colony.**
  Survives, mechanism changes: colours move from CSS selectors into JS draw calls. They
  must still be *read from* the CSS custom properties in
  `apps/map/src/styles/colony-theme.css`, resolved once via
  `getComputedStyle(document.documentElement).getPropertyValue(...)`. Hardcoding a hex in
  the renderer breaks D-004 and `spec/00-rules.md`'s "Per-colony custom CSS or themes —
  never build" row loses its enforcement point.
- **D-009 — Leaflet `CRS.Simple` as a pan/zoom container only, not its vector layer.**
  **Upheld, and more literally than before.** Amended mid-build 2026-08-22 after measuring
  the alternative: Leaflet stays as the gesture host and the canvas becomes a custom
  `L.Layer` sized to the *viewport*, replacing the two `svgOverlay`s. Measured, this page
  vs a standalone canvas with no Leaflet at all:

  | Path | Leaflet-hosted canvas | SVG overlay (today) |
  |---|---|---|
  | Discrete zoom steps | **40 fps** | 6 fps |
  | Leaflet animated zoom | **60 fps** | 6 fps |
  | Pan | **60 fps** | 60 fps |

  Standalone canvas measures ~58 fps on the discrete-step path, so hosting inside Leaflet
  costs ~8 ms there and nothing on the two paths a finger actually produces. That is a
  cheap price for pinch, drag and inertia that are already hardened on mobile Safari —
  the target device, and the riskiest thing in this rewrite to write by hand.
  **Still write a new decision (next free ID, `D-027`)** recording the canvas layer and
  amending D-022's "second Leaflet SVG overlay" mechanism. D-009 is *not* superseded.
  Do not edit any past row; append, per `DECISIONS.md`'s own rule.
- **The Y flip is back, so isolate it.** `L.CRS.Simple` maps latitude to `-y`, so a
  Leaflet centre must be converted to SVG space as `(lng, viewBoxHeight - lat)`. This
  mismatch has already caused one real bug in this codebase. It belongs in exactly one
  tested function, called by the layer and the picker alike — never inlined twice.
- **D-022 — ground texture is a mirror-tiled real photo rendered as a second Leaflet SVG
  overlay.** The photo and the mirror-tiling survive; the "second Leaflet SVG overlay"
  mechanism does not. Amend D-022 in the same new row.
- **D-025 + invariant 2 — no colony is a deliverable until a human verified it**, and the
  upload screen's confirmation, shown in front of the rendered map, is the only code path
  that writes `verified: true`. This is why the preview moves in the same unit. See §3.
- **Invariant 7 — no source file over 250 lines**, enforced by `.claude/hooks/filesize.sh`.
  The renderer will not fit in one file. Plan for that up front rather than discovering it
  at the hook.
- **Invariant 3 — money is integer paise.** Untouched here, but the detail sheet the picker
  feeds still renders it; do not "helpfully" reformat anything on the way past.

## 2. The exact task

### 2.1 New — the renderer

Split to stay under invariant 7's 250 lines. Suggested seams (names open, boundaries not):

- **A parse step** — SVG text → a plain draw model: plots (`id`, `Path2D`, `Point[]`,
  bbox), decor by class, labels (`x`, `y`, `rot`, `size`, `text`), viewBox `w`/`h`. Runs
  once per colony. Must drop trees (`.tree` elements and the `#tree-canopy` symbol) —
  new behaviour in this unit, see `isTree()`.
- **A theme step** — resolve every `--colony-*` custom property this renderer needs, once,
  into a plain object. D-004's enforcement point.
- **A draw step** — the ordered painter. Ground → decor → plot fills → plot strokes →
  labels → selection → dimension callout.
- **A picker** — screen (x, y) → plot id or null.
- **A view step** — pure maths over `{scale, cx, cy}` plus a viewport: visible bounds for
  culling, and world/screen conversion for the picker. **Gestures are Leaflet's**, per the
  D-009 amendment above; do not hand-roll pan, pinch, wheel or inertia.
- **A Leaflet layer** — an `L.Layer` owning a viewport-sized canvas, repositioned via
  `L.DomUtil.setPosition(canvas, map.containerPointToLayerPoint([0, 0]))` on
  `move`/`zoom`/`viewreset`, redrawing each time. The canvas is **never** sized to the
  colony; that is the whole reason this is fast, and sizing it to content would walk
  straight back into the 198–237 ms settle.

New tests required:

1. **Picker agreement** — for every plot in the shared fixture, its own centroid picks

2. **Picker rejects empty space** — a point outside every plot returns `null`, not the
   nearest plot.
3. **Theme resolution** — the renderer reads `--colony-status-booked` (etc.) from CSS

4. **Trees are dropped** — parsing an SVG containing `<use class="tree">` yields no tree in

5. **Label fallback** — a label with no `data-rotation` / `data-label-height` parses to

6. **Feature labels and their chips render** — parsing `fixtures/shree-vatika-2/colony.svg`

   catches the renderer silently dropping the labels the pipeline is about to start
   emitting.

### 2.6 `plotGeometry.ts` had to change after all — the plan was wrong

§1 lists `plotGeometry.ts` as "pure, already tested, **unchanged by this plan**". Both
halves of that were false and the build found out immediately.

- It had **no tests at all**.
- `parsePlotPoints` matched only `M x,y L x,y` — the pipeline's grammar. The shared
  fixture is hand-authored and uses `M100 1136.82 H180 V1283.49 H100 Z`: horizontal/
  vertical shorthand, space-separated. So it returned an **empty array for every plot in
  `fixtures/shree-vatika-2/colony.svg`**, and the canvas picker could not hit a single one.

This was latent, not new. `plotDimensionOverlay.ts` calls the same function, and its
`rawPoints.length < 3` guard silently drew nothing — so the dimension callout has never
worked on the fixture colony, on the one colony every test uses, without a single failure.

Extended in place to read both grammars (`M`/`L`/`H`/`V`/`Z`, absolute, comma or
whitespace), as a strict superset: pipeline output parses to identical results. An
unrecognised command has its numbers skipped rather than misread as coordinates, so a
future hand-drawn arc cannot invent vertices. `apps/map/src/lib/colony/plotGeometry.test.ts`
is new and pins both grammars plus the skip behaviour.

**This is a Tier 2 change (`lib/colony/**`) that the plan did not authorise.** Flagged here
rather than buried in the diff, and called out in the report for `/review`.

### Feature labels — render them, do not invent or filter them

Owner tweaks, 2026-08-22. Three things, only one of which is this unit's job.

- **Road texts (`9.0 M W ROAD`, `6.0 M W PATHWAY`, `road to Sailana`) are missing on real
  colonies.** Verified: `pipeline/export/svg.py` **never emits `<text class="feature-label">`
  at all** — line 40 names the class only inside the fallback CSS string. The hand-authored
  `fixtures/shree-vatika-2/colony.svg` has 11 of them, which is where they were last seen;
  `tools/pipeline/out/jai-dev-residency/colony.svg` has **0 feature-label and 0
  entrance-label**. This is a Tier 1 pipeline gap, **not a renderer bug and not this unit**
  (§4). What this unit owes: the canvas renderer must render `feature-label` and
  `entrance-label` — with the white chip — at full fidelity, so the moment the pipeline
  emits them they appear. The shared fixture exercises this path, so it is testable today.
- **Chip geometry is pinned**: white `rgba(255,255,255,0.94)` rounded rect, `rx` **3**,
  padding **5** horizontal / **3** vertical, behind 12px bold `#201c14` text, and the chip
  takes the label's own rotation. Plot numbers stay bare — owner's reference render.
- **No text for "Future planning" / "Reserved" etc.** This is a rule for whoever emits
  labels, **not a filter in the renderer.** A keyword blocklist here would be colony-specific
  logic living in code, which `spec/00-rules.md`'s pipeline never-build table forbids
  ("Per-colony hardcoded constants — anything colony-specific goes in that colony's config
  file, never in code"). The renderer draws every `feature-label` the contract hands it.
  Recorded against the pipeline unit in `PROGRESS.md → Deferred`.
- **Trees on roads** — resolved, cause found. `pipeline/export/run.py:63` reads
  `tree_areas = [("road", road), *(...gardens...)]`: trees were scattered onto the road
  deliberately. All trees are now stripped at parse, so nothing renders on a road today.

### Rendering decisions already settled by measurement

- **Draw plot fills per plot. Do not batch them by status.** Zero measured benefit, and
  batching composites the 0.38 tint once across the union instead of per plot, so any two
  overlapping rings render lighter than they do today. A subdivided or cut-out plot is
  exactly where that shows.
- **Batch plot strokes into a single `Path2D`.** −1.0 ms, opaque, no blending involved.
- **Cull labels to the viewport. Not optional.** 55% of an un-culled frame. Desktop
  measurements are dpr 1.25 on 943×719; a phone at dpr 3 pushes ~2.7× the pixels and every
  fill-bound number scales with it.
- **Keep hiding labels and (now absent) trees below the zoom-detail threshold.** `spec/06`.
- **No raster proxy, no static snapshot, no tile pyramid.** At 17 ms worst case the
  renderer draws live every frame and stays crisp at every zoom. A snapshot costs 108–143 ms
  — as much as it saves. Explicitly rejected, not overlooked.
- **Picker: point-in-polygon is primary**, via `parsePlotPoints`. 0.028 ms/click, no memory,
  and nothing to invalidate on pan or zoom — the colour-key buffer would need rebuilding on
  every view change, which is the bug this avoids. The colour-key approach stays in the
  harness as a documented alternative if a colony ever makes the linear scan hurt.
- **Canvas backing store = CSS size × `devicePixelRatio`**, with the context pre-scaled by
  dpr. Getting this wrong makes text soft on exactly the phones this app is for.

### Boundaries that must not move

- `attachSync`'s callback interface.
- `applyPlotTransition()` — invariant 4, the single path for status change. The renderer
  never writes plot state; it renders it and reports clicks.
- `contract/` — no change. If this plan seems to need one, stop.
- `plotGeometry.ts` — pure, reused, unchanged.
- The `"Indicative layout — not to scale"` note.

## 6. Failure modes

This unit does not itself write plot state — but it renders the screen that gates
`verified: true` (D-025), and it replaces the surface that reports clicks into
`applyPlotTransition()`. `spec/00-rules.md`'s **apps/map — writing plot state** checklist,
walked by name:

1. **Partial writes** — N/A to the renderer; it issues no writes. The invariant to protect
   is that the *only* write path still runs through `applyPlotTransition()` and the detail
   sheet. If the picker ever grows a shortcut that sets a status directly, invariant 4 is
   gone and `plot_history` stops being evidence.
2. **Idempotency** — a double-tap on the canvas must select once, not toggle-then-reselect,
   and must not open two detail sheets. The current DOM `onClick` gets React's delegation
   for free; a raw canvas listener does not. Debounce or guard on `selectedId`.
3. **Concurrency** — untouched. Stale writes still fail loudly with the winner's name
   (D-006). The renderer must not swallow a conflict by optimistically repainting a status
   the server rejected: paint from the applied state, never from the attempted one.
4. **Orphans** — the live one. Today `plotsById.get(svgId)?.setAttribute(...)` **silently
   no-ops** when a `plots` row's `svg_id` matches no path, so an orphaned plot is invisible
   and nothing says so. The canvas renderer inherits this exactly unless told otherwise:
   **count unmatched `svg_id`s in `applyStatuses` and surface the count in the dev badge**
   (`import.meta.env.DEV`-gated, like `.colony-dev-click-badge`). Do not throw — a
   half-imported colony must still render.
5. **Dead computation** — `facing` and `is_corner` come from the manifest. The renderer
   derives geometry for drawing and picking only; it must not recompute either, and must
   not start deriving a plot's length/breadth when the manifest already carries them. The
   dimension callout's `ftPerUnit` averaging is a *rendering* estimate from stored
   `length_ft`/`breadth_ft` — keep it that way.

Two failure modes specific to this change, outside the checklist:

- **The verification gate silently verifying the wrong thing.** If §2.3 slips and the
  preview keeps its own SVG path, a human clicks "verified" against a render the map will
  never produce. This is invariant 2 defeated without a single test failing. It is the
  reason preview and map ship in one commit.
- **A theme that stops being one theme.** D-004 holds today because a colour can only be
  changed in one place. The moment the renderer carries its own hex, the guarantee is gone
  and nothing fails. Acceptance criterion 6 is the guard; keep it in `/check` too.
