## 2. The exact task

Create `tools/pipeline/pipeline/geom/` (package layout left to the implementer — one module
or several, `pipeline.geom` must be the import path) implementing, per `spec/11-pipe-
geometry.md`:

- `validate_ring(ring: Ring) -> None` — raises `GeomError` (new exception, same shape as
  `DxfConformanceError`, message includes `ring.handle` and `ring.layer`) unless the ring has
  ≥3 distinct vertices, is not self-intersecting (bow-tie), and is properly closed.
- `validate_disjoint(rings: Sequence[Ring]) -> None` — raises `GeomError` naming both
  handles if any two rings overlap by more than `AREA_OVERLAP_TOLERANCE_SQFT` (pinned below).
  Shared boundaries (touching, zero-area intersection) must pass.
- `validate_within(site: Ring, others: Sequence[Ring]) -> None` — raises `GeomError` naming
  the offending handle if any ring in `others` is not contained by `site`. Must use
  shapely's `covers`, not `contains` — see pinned constraint below.
- `simplify(ring: Ring, keep_shape: bool = False) -> Polygon` — `minimum_rotated_rectangle`
  by default; `keep_shape=True` returns the ring's own polygon unchanged (vertex count
  preserved exactly — criterion 5).
- `contains(ring: Ring, point: Point) -> bool`, `centroid(ring: Ring) -> Point`,
  `area_sqft(ring: Ring) -> float`, `nearest_edge_bearing(ring: Ring, point: Point) ->
  float` — degrees 0–360, clockwise from north, same convention as
  `pipeline.extract.dxf._resolve_north_deg` (`math.degrees(math.atan2(dx, dy)) % 360`) so
  M12/M13 can combine this with `north_deg` without a sign/direction mismatch.

Tests first (`tests/test_geom.py`), synthetic `Ring`/`Point` data only — no `ezdxf`, matching
`test_dxf.py`'s in-memory-construction style but without the DXF layer entirely, since geom
never touches the format.

## 3. Pinned constraints

- **`AREA_OVERLAP_TOLERANCE_SQFT = 0.1`** — the "hairline tolerance" spec/11 explicitly says
  to pin here, not leave as a guess. Rationale: DXF export/reimport rounding on a shared
  boundary produces overlap on the order of thousandths of a sqft at most; a genuine 2-ft-wide
  overlap strip (criterion 3's own example) against any real plot edge (tens of feet) is
  multiple sqft — 0.1 cleanly separates the two with margin either direction.
- **`CLOSE_GAP_TOLERANCE_FT = 1e-6`** — reuses the exact constant already established in this
  repo for the same purpose (`tools/cad-lisp/polygonize.py`'s `TOUCH_EPS`), for consistency.
  Must reject criterion 2's 0.001-unit gap (1e-6 is three orders of magnitude tighter, no
  knife-edge ambiguity). Write criterion 2's test first and let it drive the exact
  closure-check logic — the open question is whether "closed" means checking `points[0] ==
  points[-1]` (a ring that includes an attempted, slightly-off closing vertex) or something
  else, since M10's own rings never include a duplicate closing point at all (confirmed
  above). Resolve by what makes the spec's own criterion 2 pass, not by guessing further here.
- **`validate_within` uses `Polygon.covers`, not `Polygon.contains`.** Shapely's `contains`
  returns `False` when the inner ring's boundary touches the outer ring's boundary — which is
  the *normal* case for a perimeter plot whose outer edge sits exactly on `COL-SITE`'s
  boundary. Using `contains` would fail every perimeter plot on every real colony. This is a
  one-word bug with a huge, silent blast radius if gotten wrong — pinned explicitly so it
  isn't.
- **`GeomError`** — new exception class, same file-shape as `DxfConformanceError`
  (`pipeline/extract/dxf.py:28-29`): message always names the entity handle (and layer, where
  known). `validate_*` functions raise on failure, return `None` on success — do not switch to
  returning a bool/result object; every existing validator in this codebase raises, and a
  mixed convention is a real `/review` finding waiting to happen.
- **No file-format import anywhere in `pipeline/geom/`**: no `ezdxf`, `fitz`, `cv2`, `PIL`.
  Depending on `pipeline.extract.types` (plain dataclasses) is fine and expected.
