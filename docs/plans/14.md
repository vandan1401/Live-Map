# Plan 14 — M13: pipeline/derive and pipeline/export, the automatic QA gate

**Spec:** `spec/13-pipe-derive-export.md`. **Tier 1** for the milestone as a whole
(`tools/pipeline/pipeline/export/**` is Tier 1 by CLAUDE.md's risk table — it produces the
`contract/`-shaped SVG/manifest the app consumes); `tools/pipeline/pipeline/derive/**` stays
Tier 2 by path, per spec/13's own header, so a later isolated tweak to one derived field does
not need full ceremony. This plan builds both in one pass because nothing derived can be
checked without exporting something to look at (spec/13's own framing).

This is also the **first orchestration** of the whole pipeline end to end — nothing today
calls `pipeline.geom.validate_*` or `pipeline.matching.{assign_plot_numbers,classify_features}`
from outside their own modules/tests (confirmed by grep). M12's plan explicitly deferred that
wiring here: "filtering by layer is the caller's job ... a CLI wiring or a later M13
orchestration step" (`docs/plans/13.md` §1).

## 1. Context already true

- **M10, M11, M12 are built.** `pipeline.extract.dxf.ingest_dxf(path, config) ->
  DxfIngestResult(rings, labels, north_deg, config)` reads a conforming DXF.
  `pipeline.geom` gives `validate_ring`, `validate_disjoint`, `validate_within`, `simplify`,
  `contains`, `centroid`, `area_sqft`, `nearest_edge_bearing`, `GeomError` — all pure, all
  operating on `Ring`/`Point` from `pipeline.extract.types`, no file-format import.
  `pipeline.matching.assign.assign_plot_numbers(rings, labels, config) -> PlotMatchResult`
  (`.plots: tuple[MatchedPlot(ring, label, svg_id, block, number), ...]`,
  `.default_block_count`, `.explicit_block_count`) and
  `pipeline.matching.classify.classify_features(rings, labels) ->
  tuple[ClassifiedFeature(ring, label, feature_class, kind), ...]` resolve identity and
  classification, raising `pipeline.matching.MatchingError` (same raise-and-name-the-handle
  shape as `DxfConformanceError`/`GeomError`) on any ambiguity. Reuse all of these directly —
  do not reimplement matching, containment, or ring validation here.
- **`ColonyConfig` (`pipeline/extract/types.py`) has no `px_per_ft` field, and this plan does
  not add one.** Resolved during planning (see §3) — the contract's own invariant that
  viewBox width is always exactly 1000 (D-110, `contract/SPEC.md`) can only hold if the pixel
  scale is *derived* from the site's real width, not asserted as a fixed config constant, so
  `px_per_ft` is computed at export time and written into the manifest, never read from
  config. `config.units == "ft"` (already a required field, already present in
  `colonies/shree-vatika-2.json`) is the only "asserted" unit fact — real ring geometry in a
  conforming DXF is already in real feet, so `pipeline.geom.area_sqft(ring)` needs no scale
  factor applied to produce a real `area_sqft`. No `contract/` or `ColonyConfig` schema change
  is needed for this plan (confirmed: no Task-0 prerequisite like M12's, this plan starts
  clean against the current contract).
- **The DXF layer→role split, needed before calling matching, is not done anywhere yet.**
  `DxfIngestResult.rings` mixes `COL-SITE`/`COL-PLOT`/`COL-GARDEN`/`COL-AMENITY`/`COL-WATER`;
  `.labels` mixes `COL-PLOT-NO`/`COL-FEATURE-NO`. This plan's orchestration step does that
  split (by `ring.layer`/`label.layer` equality against the constants in
  `pipeline/extract/dxf.py`, or a local copy — implementer's call).
- **Confidence is fixed at `"manual"`.** M12's plan (`docs/plans/13.md` §3) already decided
  this belongs to the manifest layer: "spec/12 says it is always written as `manual` on this
  path ... that field belongs to the manifest M13/export produces." `PlotMatchResult` has no
  confidence field; this plan's manifest builder hardcodes the literal string `"manual"` for
  every plot.
- **Feature `svg_id` construction was explicitly left undone by M12** (`docs/plans/13.md`
  §4: "Task 2's return value stops at `class`/`kind`/label/ring — it does not produce
  anything shaped like a `features[]` manifest entry"). This plan does it: **feature
  `svg_id = f"{feature_class}-{ring.handle.lower()}"`** — the DXF entity handle is a stable,
  unique-per-drawing identifier assigned once in AutoCAD and preserved across saves, which is
  exactly the property invariant 5/"silent re-identification" (spec/00-rules.md) needs: the
  same DXF re-ingested produces the same feature ids, and two distinct features (even with
  identical label text, e.g. two rings both labelled "Garden") can never collide. Do not
  derive feature ids from label text — it is human-authored and not guaranteed unique.
- **The manifest's `plots[].centroid` is in SVG pixel space, not real feet** — confirmed by
  cross-referencing the existing hand-traced `fixtures/shree-vatika-2/colony.json` against its
  paired `colony.svg`: plot-A-01's manifest centroid `[140, 1210]` exactly matches the
  midpoint of its SVG path `M100 1136.82 H180 V1283.49`. `area_sqft`/`length_ft`/`breadth_ft`
  are real feet, unscaled (1650 sqft = 30 × 55, matching the plan's real dimensions exactly).
  So: centroid goes through the export transform (§2 Task 2); area/length/breadth are computed
  directly from the raw (pre-transform) `Ring` via `pipeline.geom`.
- **`length_ft`/`breadth_ft` convention, read off every row of that same fixture**:
  `length_ft` is always the *shorter* side of the plot's bounding rectangle, `breadth_ft`
  always the *longer* — consistent across all 26 rows (e.g. `30/55`, `35/55`, `30/65`,
  never the reverse). Use `pipeline.geom.simplify(ring)` (already returns
  `minimum_rotated_rectangle`) for the two side lengths, then `length_ft, breadth_ft =
  sorted(sides)`.
- **`fixtures/shree-vatika-2/colony.svg` is hand-traced, not pipeline-generated** — its own
  manifest says so explicitly ("not pipeline-generated (tools/pipeline is pre-M9)"), and it is
  missing things this plan's spec requires of a real export (no `<use>` trees, no embedded
  `<style>` fallback block). **Do not try to byte-match it.** It exists to prove the app half
  works against *some* real colony; it is not this plan's golden target. The actual golden
  fixture (`fixtures/shree-vatika-2/colony.dxf`) still does not exist (same blocker as
  M10/M11/M12), so criteria 1-3 and 6 in spec/13's own table are **adapted**, the same way
  M10/M11/M12's were — synthetic DXF-shaped `Ring`/`Label` data built in-memory, per §5.
- **No orchestration entry point exists yet.** `pipeline/cli/ingest.py` (M10) only reports
  what a DXF contains; it does not call geom/matching/derive/export. The root and
  `tools/pipeline` Makefiles already have a stub: `export: @echo "export not built yet (M13 —
  pipeline/export/)"; exit 1` — this plan replaces that stub with a real target.
- **`tools/pipeline/out/` does not exist yet.** This plan's orchestration writes
  `out/<colony_id>/colony.svg` and `out/<colony_id>/colony.json`. Per CLAUDE.md, Claude must
  never delete a file under `tools/pipeline/out/` — writing new/overwritten exports there
  during normal operation is fine and expected; do not add any cleanup/delete step.
- **`tools/pipeline/verify/` (the local preview page, spec/14, M14) does not exist and is out
  of scope** — separate spec, separate milestone, not part of this plan (see §4).

## 2. The exact task

All new code under `tools/pipeline/pipeline/{derive,export}/` and one new
`tools/pipeline/pipeline/cli/export.py`, plus tests. Follow the existing module conventions
(`pipeline/matching/`: one small `__init__.py` holding the shared exception, one file per
concern, `@dataclass(frozen=True)` return types, raise-and-name-the-handle errors).

**Task 1 — `pipeline/derive/`** (Tier 2):

- `pipeline/derive/__init__.py`: `DeriveError` exception (same shape as `GeomError`/
  `MatchingError`) and `stable_seed(colony_id: str) -> int` — **must** use a hash stable
  across processes (`hashlib.sha256(colony_id.encode()).hexdigest()`, not the builtin
  `hash()`, which is salted per-process by `PYTHONHASHSEED` and would break the
  run-twice-get-identical-output requirement, D-105, criterion 6). Shared by `trees.py`.
- `pipeline/derive/roads.py`: `derive_road(site: Ring, others: Sequence[Ring]) ->
  BaseGeometry` — `Polygon(site.points).difference(unary_union([Polygon(r.points) for r in
  others]))`. `others` is every `COL-PLOT`/`COL-GARDEN`/`COL-AMENITY`/`COL-WATER` ring for the
  colony. Never read a road layer from the source (D-104) — there is none; roads are pure
  subtraction.
- `pipeline/derive/trees.py`: `scatter_trees(colony_id: str, areas: Sequence[tuple[str,
  BaseGeometry]]) -> tuple[Point, ...]` — `areas` is `[("road", road_geom), *(("garden",
  ring-derived polygon) for each garden ring, ordered by ascending `ring.handle` for
  determinism)]` (order matters for byte-identical reruns, criterion 6 — never iterate a
  `dict`/`set` here). For each area: buffer inward by `TREE_INSET_FT`, sample a grid at
  `TREE_SPACING_FT`, jitter each sample point by up to `TREE_JITTER_FT` using
  `random.Random(stable_seed(colony_id))` drawn in a fixed order. Constants, named and
  commented per tier-2.md's "Numbers" rule: `TREE_SPACING_FT = 25.0`, `TREE_INSET_FT = 5.0`,
  `TREE_JITTER_FT = 3.0`.
- `pipeline/derive/facing.py`: `resolve_facing(plot: Ring, road: BaseGeometry, north_deg:
  float) -> str`. From the plot's centroid (`pipeline.geom.centroid`), find the nearest point
  on `road`'s boundary (`shapely.ops.nearest_points`), take its bearing via the same formula
  as `pipeline.geom.nearest_edge_bearing` (`math.degrees(math.atan2(dx, dy)) % 360` — do not
  import/extend `nearest_edge_bearing` itself, it is typed for `Ring`, not an arbitrary
  derived `BaseGeometry`; a small local helper is the correct shape here, not a change to
  `pipeline/geom/`). Per spec/13's literal text, add `north_deg`: `true_bearing = (raw_bearing
  + north_deg) % 360`. Snap to the nearest of 8 compass points (`FACING_POINTS = ("north",
  "north-east", "east", "south-east", "south", "south-west", "west", "north-west")`, 45°
  bins, `round(true_bearing / 45) % 8`). **This sign convention cannot be numerically verified
  without a real oriented DXF** (the golden fixture doesn't exist) — flag for `/review`, and
  note in `PROGRESS.md` that it needs a sanity check against a real north-marked colony once
  one exists.
- `pipeline/derive/corner.py`: `is_plot_corner(plot: Ring, road: BaseGeometry) -> bool`. For
  each edge of `plot` (consecutive vertex pairs), intersect the edge with `road` and keep
  edges whose shared length exceeds `ROAD_TOUCH_MIN_LENGTH_FT = 1.0` ("touching" — a hairline
  contact from draughting slop must not count, mirroring `AREA_OVERLAP_TOLERANCE_SQFT`'s own
  reasoning in `pipeline/geom`). Compute each touching edge's undirected bearing (`% 180`, an
  edge and its reverse are the same side). Two touching edges count as the *same* side, not
  two, if their bearings differ by less than `CORNER_ANGLE_TOLERANCE_DEG = 20.0`. `is_corner`
  is true iff at least two touching edges remain after that dedup ("two or more non-parallel
  sides", spec/13).

**Task 2 — `pipeline/export/`** (Tier 1):

- `pipeline/export/__init__.py`: `ExportError` exception, same raise-and-name shape, reused
  by `qa.py` and (only if truly needed) `manifest.py`/`svg.py`.
- `pipeline/export/normalise.py`: `VIEWBOX_WIDTH_PX = 1000` (D-110, `contract/SPEC.md`: "always
  1000"). `Transform` frozen dataclass carrying whatever `apply_transform` needs (min-x,
  min-y, scale, and the site's transformed height, at minimum). `compute_transform(site:
  Ring) -> Transform` — scale = `VIEWBOX_WIDTH_PX / (max_x - min_x)` of the site ring; this
  scale **is** `px_per_ft`, and is what gets written into the manifest's `colony.scale`, never
  read from anywhere. `apply_transform(t: Transform, point: Point) -> Point` — translate so
  site min-x/min-y is 0, flip Y (`y' = site_height_ft - y` before scaling, or equivalent — CAD
  counts up, SVG counts down, D-110), then scale by `t.scale`. Every coordinate emitted to the
  SVG and every manifest centroid goes through this one function — do not duplicate the
  transform math anywhere else.
- `pipeline/export/svg_paths.py`: `polygon_to_path_d(geom: BaseGeometry, t: Transform) ->
  str` — handles both `Polygon` (exterior + `.interiors` as separate `M...Z` subpaths, for a
  road/site with holes) and `MultiPolygon` (each member's own subpaths), every coordinate run
  through `apply_transform`. Reused by `svg.py` for site boundary, road, and every
  garden/amenity/water/plot polygon.
- `pipeline/export/svg.py`: `build_svg(t: Transform, site: Ring, road: BaseGeometry, plots:
  Sequence[MatchedPlot], features: Sequence[ClassifiedFeature], trees: tuple[Point, ...]) ->
  str`. Emits, per `contract/SPEC.md`: `<path class="site-boundary">`, one `<path
  class="road">` (the compound path from `svg_paths.polygon_to_path_d`), one `<path
  class="{garden|amenity|water}" data-kind="{kind}" id="{feature.svg_id}">` per feature, one
  `<path class="plot" id="{plot.svg_id}">` per plot, one `<text class="plot-label">` per
  plot, one `<use href="#tree-canopy" width="..." height="...">` per tree point (**explicit
  width/height, mandatory** — contract/SPEC.md's own documented failure: without them a
  `<use>` defaults to 100% viewport and every tree covers the whole map; this already happened
  once and is a named contract rule, not a suggestion). Defines `<symbol id="tree-canopy">`
  once in a `<defs>` block (a plain circle, no fill/stroke/style — styled entirely by the
  app's CSS). Embeds one minimal fallback `<style>` block inside the `<svg>` root (spec/13:
  viewable standalone during QA; the app's own stylesheet overrides it) — a short, hardcoded
  block, not configurable. **Zero `fill`/`stroke`/`style` attributes on any emitted element
  outside that one fallback `<style>` block's own CSS text** — verified by the same grep the
  QA gate and the acceptance table both use.
- `pipeline/export/manifest.py`: `build_manifest(config: ColonyConfig, t: Transform, plots:
  Sequence[MatchedPlot], features: Sequence[ClassifiedFeature], north_deg: float) -> dict`.
  Builds the exact shape in `contract/colony.schema.json`: `colony.viewbox = [0, 0,
  VIEWBOX_WIDTH_PX, transformed_site_height]`, `colony.scale.px_per_ft = t.scale`,
  `colony.north_deg = north_deg`, `colony.generated = date.today().isoformat()`,
  `colony.verified = False` (hardcoded — invariant 2, D-108; no parameter, no override, ever),
  `colony.source = config.source` (already the right shape). Per plot: `svg_id`, `block`,
  `number`, `area_sqft = round(pipeline.geom.area_sqft(plot.ring))`, `length_ft`/`breadth_ft`
  (§1's sorted-rectangle-sides rule), `centroid = apply_transform(t,
  pipeline.geom.centroid(plot.ring))`, `facing` (Task 1), `is_corner` (Task 1), `confidence =
  "manual"` (hardcoded, §1). Per feature: `svg_id = f"{feature_class}-{ring.handle.lower()}"`
  (§1), `class = feature_class`, `kind`, `label = label.text`, `centroid` (transformed),
  `area_sqft = round(pipeline.geom.area_sqft(ring))`.
- `pipeline/export/qa.py`: `run_qa(manifest: dict, out_dir: Path, allow_id_change: bool) ->
  None`, raising `ExportError` (naming the offending id/count/value) on the first failure.
  Blocking checks per spec/13, all against the assembled `manifest` dict (defense in depth —
  most are already guaranteed by matching, but qa.py re-derives them independently rather than
  trusting upstream, per "the QA gate ... is blocking, not advisory"):
  - Every plot and feature `svg_id` is non-empty (`any polygon lacks an id`).
  - No `svg_id` repeats across the **combined** `plots` + `features` list (`any id is
    duplicated`) — a strictly broader check than `assign_plot_numbers`'s own plot-only
    duplicate check, since it also catches a plot id colliding with a feature id.
  - `len(plots) == config.expected_plots` (`the plot count disagrees with expected_plots`).
  - Every plot's `area_sqft` falls in `[PLOT_AREA_SQFT_MIN, PLOT_AREA_SQFT_MAX] = [300,
    6000]` (§3 — the scale/sanity check replacing D-111's calibration; catches "DWG in
    millimetres read as feet" per spec/13, since a unit mismatch is off by roughly `304.8²
    ≈ 93,000×` in area either direction — no plausible band tuning lets that through by
    accident).
  - No two plot polygons overlap beyond `pipeline.geom.AREA_OVERLAP_TOLERANCE_SQFT` — reuse
    `pipeline.geom.validate_disjoint` on the plot rings directly (`any two plot polygons
    overlap`); do not reimplement pairwise overlap.
  - Every plot's `number` has no more digits than `config.number_width` (`any plot number
    exceeds number_width`) — `assign_plot_numbers` already guarantees this by construction,
    but re-check the assembled manifest value, defense in depth, same reasoning as the
    duplicate-id check above.
  - **Id stability**: if `out_dir / "colony.json"` already exists, load it; if any `svg_id`
    in its `plots` + `features` is absent from the new manifest's `plots` + `features`, raise
    `ExportError` naming every missing id — unless `allow_id_change` is true.
- `pipeline/export/run.py`: `orchestrate_export(colony_id: str, dxf_path: Path, colonies_dir:
  Path, out_dir: Path, allow_id_change: bool = False) -> None` — the one place that calls
  everything in order: `load_colony_config` → `ingest_dxf` → split rings/labels by layer (§1)
  → `validate_ring` on every ring → `validate_within(site, others)` → `validate_disjoint`
  (plots only, or all — implementer's call, `validate_disjoint`'s own docstring already
  covers "shared boundaries are normal") → `assign_plot_numbers` → `classify_features` →
  `derive_road` → `scatter_trees` → `resolve_facing`/`is_plot_corner` per plot →
  `compute_transform` → `build_svg` → `build_manifest` → `run_qa` → write both files. **Both
  files or neither** (failure-mode checklist #1, §6) — build both strings fully in memory,
  run `run_qa` against the in-memory manifest, and only write to disk (`out_dir /
  "colony.svg"`, `out_dir / "colony.json"`) after every check has passed; if anything raises
  before that point, `out_dir` is untouched.

**Task 3 — `pipeline/cli/export.py`** (Tier 3 — thin shell only, no geometry/matching/
file-format logic per tier-3.md):

- `argparse`: `--colony` (required), `--dxf` (required, `Path`), `--out` (default
  `tools/pipeline/out`, resolved the same way `_COLONIES_DIR` is in `cli/ingest.py`),
  `--allow-id-change` (flag).
- Calls `orchestrate_export`. Catches `DxfConformanceError | GeomError | MatchingError |
  DeriveError | ExportError`, prints `f"error: {exc}"` to stderr, returns 1 — same idiom as
  `cli/ingest.py`'s existing `except DxfConformanceError`. On success, print the two written
  paths and return 0.
- Wire both Makefiles' `export` targets to it: `tools/pipeline/Makefile`'s stub becomes `$(PY)
  -m pipeline.cli.export --colony $(COLONY) --dxf $(DXF)`; root `Makefile`'s (currently
  missing entirely — add one) becomes `$(MAKE) -C tools/pipeline export COLONY=$(COLONY)
  DXF=../../$(DXF)`, matching the existing `ingest`/`inspect` delegation pattern.

**Task 4 — tests**, following `tests/test_matching.py`'s synthetic-construction convention
(small in-memory `Ring`/`Label`/`ColonyConfig`, no `ezdxf`/live DXF past the extract layer):

- `tests/test_derive.py` — one test per derive function's core behaviour, plus the
  determinism assertion (`stable_seed` returns the same value across two separate Python
  process invocations — assert by calling it twice in the *same* test process is not enough
  proof, since that would pass even with the broken builtin `hash()`; instead assert the
  literal returned integer against a hardcoded expected value, so a future accidental
  regression back to `hash()` is caught even within one process).
- `tests/test_export.py` — normalise/svg/manifest/qa, one test per §5 criterion below.

## 3. Pinned constraints

- **`px_per_ft` is derived, never read from config** — see §1. This is a deliberate deviation
  from spec/13's literal phrase "`px_per_ft` is asserted in the colony config"; the reasoning
  (viewBox width must always be exactly 1000, D-110/`contract/SPEC.md`, which is incompatible
  with a fixed human-supplied scale for an arbitrary site width) is pinned here for `/review`
  to scrutinize specifically — this is the one place this plan knowingly reads the spec
  narrowly rather than literally.
- **`PLOT_AREA_SQFT_MIN = 300`, `PLOT_AREA_SQFT_MAX = 6000`** — a residential sanity band
  loose enough for smaller/larger real plots than the fixture's own 1000–1950 sqft range, but
  tight enough that a units mistake (~93,000× either direction, §2) can never land inside it.
  Named constants in `qa.py`, per tier-2.md's "Numbers" rule.
- **`TREE_SPACING_FT = 25.0`, `TREE_INSET_FT = 5.0`, `TREE_JITTER_FT = 3.0`**,
  **`ROAD_TOUCH_MIN_LENGTH_FT = 1.0`**, **`CORNER_ANGLE_TOLERANCE_DEG = 20.0`** — named
  constants in their respective `derive/` modules, each with the one-line rationale already
  given in §2. These are first-cut values with no real colony to tune against yet (same
  situation M11's `AREA_OVERLAP_TOLERANCE_SQFT` was in) — note in `PROGRESS.md` → `##
  Deferred` that they may need revisiting once a real DXF exists.
- **Feature `svg_id = f"{feature_class}-{ring.handle.lower()}"`** — see §1's rationale (DXF
  handle stability, not label text). This is a new rule this plan introduces; once set, do
  not change the format without checking every already-exported colony's stored `svg_id`s
  against the app's `plots`/`plot_history` — a format change is exactly the "silent
  re-identification" failure mode.
- **`confidence` is always the literal string `"manual"`** on every plot this pipeline
  produces (§1, already decided in `docs/plans/13.md`). Do not thread a real confidence value
  through from matching — there isn't one; D-118 deleted the graduated-confidence ladder.
- **`verified` is always `False`, hardcoded, no parameter** (D-108, invariant 2). `qa.py`,
  `manifest.py`, and `run.py` must have no code path, flag, or parameter that can set it
  `True`. This is the single most load-bearing rule in this plan — a `/review` finding if
  violated in any form, including an unused-but-present parameter.
- **Both files or neither** (§2 Task 2's `orchestrate_export`, failure-mode checklist #1).
  Never write `colony.svg` before `run_qa` has passed against the full assembled manifest.
- **`--allow-id-change` is the only way to bypass the id-stability check**, and it never
  bypasses any other QA check — a duplicate id, a bad area, a wrong plot count, or an
  overlapping polygon must still block the export even with that flag set.
- **`facing`'s sign convention (`+ north_deg`, not `- north_deg`) is taken on spec/13's literal
  text, not independently re-derived** — flagged in §2 Task 1 for `/review` and for a real-DXF
  sanity check later (`PROGRESS.md` → `## Deferred`). Do not "fix" this to match a different
  derivation without new evidence; it would be a guess in either direction.
- **No file-format import** (`ezdxf`, `fitz`, `cv2`, `PIL`) in `pipeline/derive/` or
  `pipeline/export/` — same purity boundary as `pipeline/geom/`/`pipeline/matching/`.
  `pipeline/cli/export.py` may import `pipeline.extract.dxf` (same as `cli/ingest.py` already
  does) since the CLI layer is the one place format code is allowed to be named, even though
  it delegates the actual call to `run.py`.

## 4. Non-goals

- **`tools/pipeline/verify/` (the local preview page)** — spec/14, a separate milestone
  (M14, Tier 2). Not built here. `serve` (root and pipeline Makefiles) already exists as a
  target pointing at a directory that doesn't exist yet; leave it as-is.
- **The app's colony-upload verification screen** — already built (`apps/map/src/features/
  colony-upload/`, D-025, M15/`docs/plans/11.md`). Nothing in this plan touches `apps/map`.
- **A `source.png` reference image alongside the export** — mentioned in spec/14 (verify page)
  only, not this plan.
- **Per-kind amenity `<symbol>`s** (clubhouse/temple/tank/... icons) — re-read
  `contract/SPEC.md`'s "a new amenity type means a new `<symbol>`, not a new CSS rule" as
  describing how the **app** would render an icon overlay for a kind, not something the
  pipeline emits; amenities are rendered as plain `<path class="amenity" data-kind="...">`
  polygons, same as gardens/water. Only `tree-canopy` gets a `<symbol>` (spec/13 names it
  explicitly).
- **Golden-fixture byte-matching against `fixtures/shree-vatika-2/colony.svg`** — that file is
  hand-traced (§1), not this plan's target. The golden test (`tests/test_golden.py`) stays
  skipped, same reason as M10/M11/M12 (`fixtures/shree-vatika-2/colony.dxf` still doesn't
  exist).
- **Any change to `pipeline/geom/`'s public signatures** — `derive/facing.py` writes its own
  small bearing helper rather than generalizing `nearest_edge_bearing` to accept a
  `BaseGeometry`; extending a Tier-1 module's typed API for one caller is out of scope here.

## 6. Failure modes

This task writes state for the first time in `tools/pipeline` (files under `out/`) — walk
`spec/00-rules.md`'s pipeline checklist by name:

1. **Partial writes.** `orchestrate_export` builds both the SVG string and the manifest dict
   fully in memory, runs `run_qa` against the manifest, and only then writes both files to
   `out_dir`. Any exception before that point (a `GeomError`, `MatchingError`, `DeriveError`,
   or `ExportError`) leaves `out_dir` completely untouched — no partial `colony.svg` with no
   matching `colony.json`. Test: assert a QA failure leaves `out_dir` empty (or unchanged, for
   a re-export over an existing one).
2. **Idempotency.** Two runs on the same synthetic input produce byte-identical SVG and
   manifest strings — criterion 6. Tree scatter is seeded via `stable_seed` (hash-stable
   across processes, §2 Task 1), never `random()` or the clock; `generated` uses
   `date.today()`, which is stable within a single test run but intentionally *not* pinned
   across calendar days — a rerun on a different day is expected to update it, that is not a
   regression.
3. **Silent re-identification.** The id-stability QA check (§2 Task 2) is exactly this
   safeguard — blocking, not a warning, and the one QA check whose failure mode "lives in the
   other half of the repo" (spec/13's own words): a dropped `svg_id` orphans `plots`/
   `plot_history` rows already in Postgres.
4. **Orphans.** A polygon with no id, an id with no polygon, or a label matched twice are all
   already hard errors one layer down (`assign_plot_numbers`/`classify_features` raise
   `MatchingError` before `orchestrate_export` ever reaches derive/export) — `qa.py`'s own
   id-presence/duplicate checks are the "defense in depth" layer described in §2, not the
   first line of defense.
5. **Dead computation.** `facing`, `is_corner`, `area_sqft` are computed exactly once, in
   `orchestrate_export`, and written into the manifest. Nothing downstream (the app, or a
   future rerun reading an old export) recomputes them — the app already treats these as
   read-only manifest fields (tier-1.md, apps/map: "`facing`/`is_corner` come from the
   manifest. Nothing recomputes them").
